# 指令离线数据与审核

指令数据从仓库已有的 `upstream/riscv-isa-manual` 子模块提取，固定为发布标签 `20250508`、提交 `584390d9d872835b1bc45ab9ea946b56db3ad485`。不从 riscv-opcodes 或其他仓库补入编码，不执行手册中的 JavaScript、EDN、AsciiDoc 宏或 Sail 伪代码。

本目录数据已接入应用的 INST 搜索、编码反查和位布局详情，与 CSR 共用位宽、权限、扩展和来源筛选。提取与审核工具支持复现和检查已收录内容；应用版本和现有 CSR 数据不随本轮修改。

## 存储与覆盖范围

- `app/src/main/assets/inst/manual-{name}.json`：每个指令名一个文件；同名的位宽、扩展或寄存器文件差异存入文件内的编码变体。
- `app/src/main/assets/inst/pseudo-{name}.json`：伪指令展开及名称参考，每个名称一个文件；未定义展开的示例或历史名称明确标记，不虚构编码。
- `app/src/main/assets/riscv-instructions.json`：独立指令目录、数据版本、文件索引与 SHA-256；不混入现有 CSR 索引。
- `docs/data/instruction-import-report.json`：生成统计，仅作本地复核。
- `docs/data/instruction-review.json`：逐条审核结果、数据指纹及编码重叠分类，仅作本地复核。
- `docs/data/instruction-context-review.json`：全量上下文规则、静态样本及寄存器/保留位扫描结果，仅作本地复核。

指令 JSON 和目录固定使用 UTF-8、LF 换行，目录中的 SHA-256 对应文件实际字节，保证 Windows 与其他平台生成、Git 检出及应用加载时一致。

当前收录 **1,287 个机器指令／别名条目、1,410 个编码变体、9,958 个编码字段**。覆盖 RV32/RV64 基础整数、M、原子、浮点与半精度、压缩与 Zc、位操作、标量/向量密码、向量运算与访存、缓存操作、MOP、CFI，以及特权和 CTR 指令。其中含 88 个单指令别名，支持 CSR、标量浮点、向量、分支及手册明确保留的兼容旧名称；别名不是额外的机器指令。

另收录 **17 个参考条目**：8 个名称提供 18 种条件化展开，9 个仅保留手册示例或历史名称及来源说明。数据库版本为 `0.2.0`，目录格式为 schema 2，应用版本不变。完整名称及来源见[伪指令覆盖清单](pseudoinstruction-coverage.md)。

不收录 RV128、未分配/自定义保留空间、已淘汰的历史编码或仅在外部规范中定义的指令。伪指令只收录该手册明确给出的参考序列，不等同于所有汇编器的完整伪指令列表；不会把示例中的函数名、格式名或操作数占位符当作指令名。版本范围限于上述固定手册，不能视为后续所有 RISC-V 规范的全集。

## 数据结构

| 字段 | 含义 |
| --- | --- |
| `schemaVersion`、`id` | 格式版本及稳定身份 `riscv/manual/inst/{name}` |
| `architecture`、`namespace`、`name` | 架构、来源命名空间和小写指令名 |
| `summary`、`summaryEn` | 简短中文/英文语义；运算类允许两者使用同一公式 |
| `kind`、`aliasOf` | `instruction`、`hint` 或 `alias`；别名标明对应基础指令 |
| `sourceRevision`、`license` | 固定来源提交及 `CC-BY-4.0` 许可 |
| `semanticSources` | 语义的手册相对路径、起止行、固定版本链接、片段 SHA-256 与提取方式 |
| `encodings` | 不同位宽、扩展及寄存器文件对应的编码变体 |
| `assemblyOperands` | 可选，别名的汇编操作数顺序及有限格式标记；不是可执行代码 |

每个编码变体包含：

| 字段 | 含义 |
| --- | --- |
| `length`、`xlens` | 16/32 位指令长度，以及明确支持的 32/64 位 XLEN |
| `requires` | 扩展条件的“或”列表，内层为“且”；例如 `[["Zfa", "D"]]`。空内层表示无额外扩展，不表示可在任意特权态执行 |
| `mask`、`match` | 定长十六进制；候选匹配条件为 `(word & mask) == match` |
| `fields` | 完整编码位段，端点包含在内，覆盖全部位且互不重叠 |
| `constraints` | 保留操作数、SEW/LMUL、寄存器组、权限、虚拟化及配置条件的文字说明 |
| `encodingConstraints` | 可直接检查的掩码条件：`in` / `notIn`，可按 `xlens` 限定生效范围 |
| `operandRelations` | 解码后的操作数相等约束，例如 FNEG.S 要求 rs1 = rs2；编码反查必须检查 |
| `contextRules` | 按寄存器、舍入、状态、向量、CSR、权限等分类的上下文规则，含双语说明、来源和检查方式；空列表表示扫描未发现额外类别 |
| `sources` | 编码及派生规则的来源证据，与语义来源使用相同定位结构 |
| `summary`、`summaryEn` | 可选，覆盖同名指令的特殊语义，例如 RV32 Zilsd 寄存器对 |
| `registerFile`、`privilege` | 可选，区分 Zfinx 整数寄存器语义及特权态要求 |
| `sourceSynopsis` | 可选，保留手册原始简述以便复核 |

扩展条件记录指令所属扩展或明确的必要条件，不是完整的 ISA 依赖/冲突求解器。嵌入式向量子集、浮点元素精度、上下文控制等额外约束保留在文字条件与来源中。仅匹配 `mask/match` 不能断言指令在当前环境合法，也不能据此忽略 `encodingConstraints` 与 `operandRelations`。

编码位段包含 `name`、`msb`、`lsb`；固定字段有 `value`，变量字段有 `operand`。寄存器操作数使用 `registerClass` 区分整数、浮点和向量寄存器，避免将 E 基础架构的 x0–x15 限制错误套用到 f/v 寄存器。立即数位段可用 `operandBits` 按高位到低位列出目标操作数位序，并用 `operandSigned` 标记符号解释；未出现的低位隐含为零。标准压缩寄存器使用 `registerOffset=8`，Zcmp 的保存寄存器编码使用独立 `registerMap`，不可混用。`values` 存放舍入模式、FLI 常量等枚举，`sourceLabels` 保留图中的辅助标注。

公式中，`X/F/V` 表示寄存器文件，`M8/M16/M32/M64` 表示对应宽度的访存，`sext/zext` 表示符号/零扩展，`sext32` 表示截取低 32 位后符号扩展到 XLEN，`low32`、`signed32`、`unsigned32` 均先截取低 32 位，再按相应符号解释；`<s/<u` 和 `>>s/>>u` 区分有符号与无符号操作。标量浮点的 `a/b/c` 对应 `F(rs1)/F(rs2)/F(rs3)`；向量的 `src1` 按指令后缀取向量、标量或立即数。同一公式中的源操作数取执行前的值，避免目的寄存器重叠时产生歧义。公式省略完整异常、副作用与浮点特殊值细节，具体行为仍以来源为准。

`requires`、位段映射和摘要是声明式数据，不能作为脚本执行。Python 数据审核工具已实现部分上下文检查，后续应用解码器仍需接入这些规则，并实现剩余运行状态检查。

## 提取与复现

使用 Python 3.10+ 标准库：

```sh
git submodule update --init upstream/riscv-isa-manual
python tools/import_manual_instructions.py
python tools/review_manual_instructions.py
python tools/instruction_context.py
python -m unittest discover -s tools -p 'test_manual*.py'
```

导入前检查手册提交及未修改状态。总表按打印的 bit 位置解析，压缩指令按实际 16 位列解析；特权 Bytefield 表按其显式 bit 标头处理，不能直接把加宽的绘图比例当成编码位宽。向量指令由分配表、格式图和正文规则展开。只有手册明确给出关系时，才从基础编码派生 Zfa、Zabha、Zfinx 或别名变体。

工具只重写自身命名空间中的 `manual-*.json`，不删除其他来源文件。后续若允许多来源包，需另外定义合并与冲突规则。

## 本轮全量复核

全部条目检查身份唯一性、文件索引、双语摘要、来源与许可、位宽、扩展名、位段边界、固定值、掩码/匹配值、立即数位序、寄存器映射、枚举、约束及来源行范围/片段指纹。另用固定机器码验证基础、浮点、压缩、向量、CFI 等代表性编码，检查保留编码拒绝，并比较重新提取结果与每一份已存 JSON 是否一致。

已审阅 **163 组不同指令名之间的编码重叠**，分别记录为别名、提示特化、MOP 重定义、操作数条件分区，或互斥扩展的空间复用；未知重叠使审核失败，不任意按文件顺序消歧。完整列表见本地 `instruction-review.json`。

审核中修正的边界包括：

- RV64 总表标题中提到 RV32 的继承关系，不意味着该行也能在 RV32 执行。
- RV32 Zilsd 的 `LD/SD` 与 RV64 同名指令编码相同，但使用不同语义和寄存器对约束。
- `FENCE` 表的绘图跨度和 `FLQ` 的跨空白单元格，结合独立格式图确认实际位宽。
- VAESDF.VS 图中 `101001` 后多出的反引号，结合本章独立分配表确认，不能当成变量字段。
- `C.ADDI16SP` 图中的十进制寄存器常量 2、压缩寄存器 prime 的不同字符，以及 Zcmp 的 s0–s7 非连续整数寄存器映射。
- `CM.JT/JALT` 的索引分区、`VID.V` 的 `vs2=0`、RV32 压缩移位高位，以及 AES64KS1I 的轮编号限制。
- 不把 `Zero/Zeros` 等下一条指令的锚点标题误当成扩展名称。

这里的审核覆盖已生成数据及其提取规则，不等同于运行每条指令或完成硬件模型一致性认证。向量运行上下文、CSR 读写抑制、访存异常及权限等完整执行语义仍须遵循规范。

## 上下文全量扫描

对全部 **1,410 个编码变体**进一步构造 **2,670 个 XLEN 有效编码样本**，扫描 **199,966 次寄存器编号赋值**及 **1,381 个应被拒绝的保留位赋值**。每个变体均记录上下文扫描结果；数据工具测试共 **32 项通过**。统计可通过上述命令重新生成。

本轮补充或修正：

- E 基础架构的寄存器编号限制同时覆盖 M、CSR、整数/浮点转换、向量标量操作等扩展；f/v 寄存器不因编号大于 15 而被拒绝。
- 浮点 `rm=5/6` 的保留编码；动态舍入 `rm=7` 在缺少 `frm` 时保持待检查，`frm=5/6/7` 不作为有效模式。
- RV32 Zilsd、RV32 Zdinx 及宽 CAS 的偶数寄存器对，按实际操作数宽度及 XLEN 生效，不误限单精度目的寄存器或 RV64 的单寄存器双字操作。
- `CM.MVSA01` 的不同目的寄存器要求、E 模式的保存寄存器列表范围，以及整组向量寄存器传送的编号对齐。
- 压缩影子栈指令的 `Zcmop` 条件，以及 BF16 共用的半精度传送指令所属关系。
- `vset*` 与整寄存器访存不要求旧 `vtype.vill=0`；依赖 `vtype` 的普通指令仍检查 `vill`。
- 归约和特定掩码操作的 `vstart=0` 条件；密码元素组的 SEW、EGS、容量与长度倍数，以及向量无进位乘法/BF16 的元素宽度条件。

`tools/instruction_context.py` 的 `check_context` 仅检查已知事实，返回：

| 结果 | 含义 |
| --- | --- |
| `rejected` | 已提供事实违反编码、位宽、扩展或已实现的上下文规则 |
| `needs-context` | 缺少必要状态，或该项运行状态检查尚未完整实现 |
| `checks-passed` | 本工具已实现且适用的检查通过，不是指令必定无异常执行的保证 |

传入的扩展集合必须是调用方已展开依赖的能力集合；工具不自行假设完整 ISA 配置。缺少 `frm`、FS/VS、`vtype`、`vstart`、SEW、VLEN/LMUL 等状态时不会静默当作有效值。CSR 存在性/访问规则、虚拟化控制、页表/PMP/PMA、有效地址，以及尚未实现的完整寄存器组重叠判定，均保留明确的待检查项。

## 来源与许可

数据依据 RISC-V International 及其贡献者的 ISA Manual，进行了格式转换、名称规范化、中英文摘要、公式化说明及编码约束整理。沿用 `CC-BY-4.0` 署名，许可证见 `app/src/main/assets/licenses/CC-BY-4.0.txt`，第三方声明见 `app/src/main/assets/THIRD_PARTY_NOTICES.txt`。

## 应用查询入口

首页搜索框下方提供 CSR / INST 分页，可点击标签或左右滑动切换；两页共用搜索词、RV32/RV64、执行权限、扩展和来源筛选，并分别保留列表位置。扩展选项保留自动关联前置项的规则。CSR 多选匹配任一关联项；INST 需要完整满足至少一组 `requires` 条件（组内 AND、组间 OR），不能仅凭某个关联扩展就显示需要额外扩展的指令。不选择扩展时展示全部候选；筛选不等同于完整运行环境合法性检查。

INST 支持名称与中英文简短描述搜索，以及 `0x` 十六进制、`0b` 二进制编码反查；无前缀时支持 4 / 8 位十六进制和 16 / 32 位二进制，允许空格和下划线分组。名称匹配排在描述匹配之前，英文描述按完整单词匹配；完整指令名命中优先置顶，其他结果在各类内部按 M、S、H（含 HS）、VS、U、D 权限顺序排列；编码反查保留别名、HINT 和扩展重叠候选，并检查当前 XLEN 的静态编码限制。

指令名与描述相关结果分为纵向排列的可折叠分类，默认展开，空分类不显示；没有任何结果时才显示无匹配提示。直接输入 ret 时，完整名称 ret 排在最前，mret、sret 等片段命中和描述相关结果继续保留。不提供独立的精确搜索按钮、菜单或等号前缀语法；全部查询统一使用当前筛选与无结果诊断。

同名结果归并为一张卡片，展开后逐项显示编码、扩展、权限、来源与语义，并分别进入详情。归并仅影响显示，不删除变体、不选择一个来源覆盖其他来源；分类排序沿用原搜索优先级。分类折叠、变体展开状态与列表位置在进入详情、返回或横竖屏切换后保留。

反查出现多个候选时，可展开“为什么有多个候选？”查看别名关系、扩展条件差异、HINT 或多个来源的说明。详情中的“同编码候选”支持切换，并保留原机器码；别名名称查询也可跳转到同一来源的基础指令。候选只来自当前筛选下实际匹配的结果，不因显示关系而重新引入被扩展条件排除的候选。

指令详情展示编码变体、16 / 32 位布局、重组后的寄存器和立即数操作数、执行条件、枚举值与规范来源。执行条件说明默认收起；编码匹配不代表已确认当前机器状态可执行。详情的 RV32/RV64 切换沿用全局筛选。

## 伪指令参考

伪指令参与 INST 名称与中英文摘要搜索，沿用完整名称置顶、分类及统一筛选。88 个单指令别名参与机器码反查，并检查固定值、保留编码和操作数相等关系；汇编行采用别名自己的操作数顺序，不显示被省略的重复源寄存器。

17 个参考条目使用独立的 `InstructionPseudo` 模型，不参与机器码反查，也不展示虚构的位布局。8 个有定义的名称展示条件、改写寄存器、基础指令跳转与可复制序列；9 个示例或历史名称仅展示来源和限制，分别用 `referenceStatus=example/historical` 标记。历史名称不推定当前扩展，选择具体 ISA 扩展时不会把未知要求视为满足。

`call` / `tail` 保留 CFI 章节的结构示例，不代替完整重定位或链接器松弛规则；并不要求 Zicfilp。`vmsge{u}.vx` 各保留 5 种序列，包括 4 种掩码／临时向量寄存器情况及有边界前提的标量减一优化；vt 必须不同于 vd。`vmslt{u}.vi` / `vmsge{u}.vi` 保留 i−1 符号变换及立即数范围，不直接生成编码。`li` / `la` 的通用展开不在该 ISA manual 中定义，故只保留名称参考；历史 MFTX 等名称也不据名称相似推定当前位编码。

目录通过 `pseudoFiles` / `pseudoFileHashes` 索引参考条目；schema 2 声明 `requiredFeatures`：`operand-relations-v1`、`alias-assembly-v1`、`pseudo-references-v1`。新应用仍可读取不使用新特性的 schema 1 目录；旧应用拒绝 schema 2，避免静默忽略影响反查正确性的操作数约束。

生成器 `manual_aliases.py` / `manual_pseudoinstructions.py` 与主导入流程联动。`manual_pseudo_coverage.py` 扫描固定手册全部 72 个 AsciiDoc 源文件，逐项审核 77 处相关声明／提及和 980 行汇编形态示例，共覆盖 105 个名称；未知声明、未归类示例或清单缺项使审核失败。陷阱记录中的特殊伪指令值明确归类，不作为汇编指令入库。本地报告为 `docs/data/pseudo-coverage-review.json`，不作为发布数据。

审核同时检查双语内容、来源行及指纹、基础名称、向量字面序列、索引／哈希／LF、重新生成一致性及每个别名与基础编码的有效样本；测试包括相等约束的反例。当前提供查询与反查，不接受完整汇编语句，也不执行伪指令展开或生成机器码。

## 反查呈现与诊断

### 部分编码查询

单条编码支持 `?` 通配符：十六进制每个 `?` 代表 4 个未知位，二进制每个 `?` 代表 1 个未知位。允许空格与下划线分组。带通配符时必须给出完整长度，不自动在高位补零：

| 输入形式 | 长度与进制 |
| --- | --- |
| `0x00?50533` / `00?50533` | 8 位十六进制，即 32 位指令 |
| `0x00?0` / `00?0` | 4 位十六进制，即 16 位指令 |
| `0b00000000????01010000010100110011` | 32 位二进制 |
| 无前缀、仅含 `0/1/?` 的 16 或 32 个字符 | 二进制 |

无前缀的 4 / 8 个字符固定按十六进制解释，因此 `000?0011` 是 32 位十六进制模式。搜索结果标明识别到的进制、位宽与已知位数；已知低位与所选指令长度冲突时提示检查格式。完整编码原有的 `0x13` 等省略前导零行为保持不变。

匹配要求存在至少一个同时满足查询已知位、固定编码、当前 XLEN 静态限制及操作数相等关系的完整编码。未知位不当作零；例如零立即数被保留的 C.ADDI4SPN，在未知位可补成非零时仍是候选。求解只围绕数据中明确的静态约束，不执行指令或推定运行状态。

部分编码沿用扩展、权限、来源与位宽筛选，以及同名变体归并、多候选说明和详情跳转。详情保留原模式；只有用户已经提供该操作数的全部编码位时才展示解码值，其余显示“未确定”，不生成或复制完整汇编。候选之间可能对应不同的完整机器码。

16 位模式至少需要 5 个已知位，32 位模式至少需要 7 个已知位；当前筛选后超过 100 个指令名称时，提示补充已知位或缩小筛选，避免大量低信息候选。功能只处理单条部分编码，不含批量输入或连续编码流拆分。

### 指令使用示例

指令详情在位布局下方展示可复制的具体汇编示例，随当前 XLEN、编码变体及寄存器命名方式生成。操作数遵守数据库中已录入的固定编码、静态限制与相等关系；常见算术、访存、跳转和 CSR 访问另附简短中文说明，并保留英文说明供未来国际化使用。示例不是手册原文摘录，也不是完整可运行程序；执行仍需满足指令对应的扩展、权限、内存及运行状态要求。

示例与查询机器码相互独立：完整或部分编码反查时明确标注，不覆盖查询值，也不把未知位补成用户输入。已有展开定义的伪指令提供具体操作数写法；li、la 使用手册已有的示例形式，历史名称不推定当前用法。尚无完整汇编格式支持的条目不生成示例。

### 完整编码反查

机器码反查同时显示汇编行与解码字段；详情可切换 ABI 名称 / x、f 寄存器编号，并复制汇编行。支持标量、浮点、压缩、原子、向量与 Zcmp 的操作数格式，保留原始编码。没有 PC 输入时，PC 相对跳转显示为 `.+偏移` 或 `.-偏移`；向量掩码、原子 aq/rl、浮点舍入及常见立即数均按语法显示。未确认的非典型编码格式仅展示并明确标记操作数字段，不伪装成已验证的汇编语句。

CSR 访问指令将地址与当前位宽、来源范围中的 CSR 对应；唯一候选可在汇编行显示名称，多个来源候选保留地址并分别提供跳转入口，未收录时保留地址。CSR 关联不使用执行权限筛选，避免因 CSR 访问指令被列为 U 类而隐藏 mstatus 等目标寄存器。返回恢复原指令、机器码、编码变体及详情位置。

无结果时分别说明输入格式、筛选排除、已知模板静态限制或数据库未收录。存在匹配候选时，可清除阻碍对应候选的位宽、权限、扩展或来源筛选，保留原输入；位宽恢复采用候选适用的 XLEN。只有固定编码模板已命中、且所有对应 XLEN 均违反明确的静态限制时，才提示已知保留编码；数据库未收录不等同于编码非法。以 0x / 0b 表示整数时允许省略前导零，无前缀编码仍使用固定长度，当前不支持连续指令及超过 32 位的指令反查。
