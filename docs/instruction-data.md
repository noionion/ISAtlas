# 指令离线数据与审核

指令数据从仓库已有的 `upstream/riscv-isa-manual` 子模块提取，固定为发布标签 `20250508`、提交 `584390d9d872835b1bc45ab9ea946b56db3ad485`。不从 riscv-opcodes 或其他仓库补入编码，不执行手册中的 JavaScript、EDN、AsciiDoc 宏或 Sail 伪代码。

本目录数据已接入应用的 INST 搜索、编码反查和位布局详情，与 CSR 共用位宽、权限、扩展和来源筛选。提取与审核工具支持复现和检查已收录内容；应用版本和现有 CSR 数据不随本轮修改。

## 存储与覆盖范围

- `app/src/main/assets/inst/manual-{name}.json`：每个指令名一个文件；同名的位宽、扩展或寄存器文件差异存入文件内的编码变体。
- `app/src/main/assets/riscv-instructions.json`：独立指令目录、数据版本、文件索引与 SHA-256；不混入现有 CSR 索引。
- `docs/data/instruction-import-report.json`：生成统计，仅作本地复核。
- `docs/data/instruction-review.json`：逐条审核结果、数据指纹及编码重叠分类，仅作本地复核。
- `docs/data/instruction-context-review.json`：全量上下文规则、静态样本及寄存器/保留位扫描结果，仅作本地复核。

指令 JSON 和目录固定使用 UTF-8、LF 换行，目录中的 SHA-256 对应文件实际字节，保证 Windows 与其他平台生成、Git 检出及应用加载时一致。

当前收录 **1,215 个条目、1,323 个编码变体、9,403 个编码字段**。覆盖 RV32/RV64 基础整数、M、原子、浮点与半精度、压缩与 Zc、位操作、标量/向量密码、向量运算与访存、缓存操作、MOP、CFI，以及特权和 CTR 指令。保留手册明确说明的少量单编码别名与计数器读取伪指令；它们不是额外的机器指令。

不收录 RV128、未分配/自定义保留空间、已淘汰的历史编码、仅在外部规范中定义的指令，或只能由多条指令展开的汇编伪指令。不会把汇编示例中的函数名、格式名或操作数占位符当作指令名。版本范围限于上述固定手册，不能视为后续所有 RISC-V 规范的全集。

## 数据结构

| 字段 | 含义 |
| --- | --- |
| `schemaVersion`、`id` | 格式版本及稳定身份 `riscv/manual/inst/{name}` |
| `architecture`、`namespace`、`name` | 架构、来源命名空间和小写指令名 |
| `summary`、`summaryEn` | 简短中文/英文语义；运算类允许两者使用同一公式 |
| `kind`、`aliasOf` | `instruction`、`hint` 或 `alias`；别名标明对应基础指令 |
| `sourceRevision`、`license` | 固定来源提交及 `CC-BY-4.0` 许可 |
| `semanticSources` | 语义的手册相对路径、起止行、固定版本链接、片段 SHA-256 与提取方式 |
| `encodings` | 不同位宽、扩展及寄存器文件对应的编码变体 |

每个编码变体包含：

| 字段 | 含义 |
| --- | --- |
| `length`、`xlens` | 16/32 位指令长度，以及明确支持的 32/64 位 XLEN |
| `requires` | 扩展条件的“或”列表，内层为“且”；例如 `[["Zfa", "D"]]`。空内层表示无额外扩展，不表示可在任意特权态执行 |
| `mask`、`match` | 定长十六进制；候选匹配条件为 `(word & mask) == match` |
| `fields` | 完整编码位段，端点包含在内，覆盖全部位且互不重叠 |
| `constraints` | 保留操作数、SEW/LMUL、寄存器组、权限、虚拟化及配置条件的文字说明 |
| `encodingConstraints` | 可直接检查的掩码条件：`in` / `notIn`，可按 `xlens` 限定生效范围 |
| `contextRules` | 按寄存器、舍入、状态、向量、CSR、权限等分类的上下文规则，含双语说明、来源和检查方式；空列表表示扫描未发现额外类别 |
| `sources` | 编码及派生规则的来源证据，与语义来源使用相同定位结构 |
| `summary`、`summaryEn` | 可选，覆盖同名指令的特殊语义，例如 RV32 Zilsd 寄存器对 |
| `registerFile`、`privilege` | 可选，区分 Zfinx 整数寄存器语义及特权态要求 |
| `sourceSynopsis` | 可选，保留手册原始简述以便复核 |

扩展条件记录指令所属扩展或明确的必要条件，不是完整的 ISA 依赖/冲突求解器。嵌入式向量子集、浮点元素精度、上下文控制等额外约束保留在文字条件与来源中。仅匹配 `mask/match` 不能断言指令在当前环境合法，也不能据此忽略 `encodingConstraints`。

编码位段包含 `name`、`msb`、`lsb`；固定字段有 `value`，变量字段有 `operand`。寄存器操作数使用 `registerClass` 区分整数、浮点和向量寄存器，避免将 E 基础架构的 x0–x15 限制错误套用到 f/v 寄存器。立即数位段可用 `operandBits` 按高位到低位列出目标操作数位序，并用 `operandSigned` 标记符号解释；未出现的低位隐含为零。标准压缩寄存器使用 `registerOffset=8`，Zcmp 的保存寄存器编码使用独立 `registerMap`，不可混用。`values` 存放舍入模式、FLI 常量等枚举，`sourceLabels` 保留图中的辅助标注。

公式中，`X/F/V` 表示寄存器文件，`M8/M16/M32/M64` 表示对应宽度的访存，`sext/zext` 表示符号/零扩展，`sext32` 表示截取低 32 位后符号扩展到 XLEN，`low32`、`signed32`、`unsigned32` 均先截取低 32 位，再按相应符号解释；`<s/<u` 和 `>>s/>>u` 区分有符号与无符号操作。标量浮点的 `a/b/c` 对应 `F(rs1)/F(rs2)/F(rs3)`；向量的 `src1` 按指令后缀取向量、标量或立即数。同一公式中的源操作数取执行前的值，避免目的寄存器重叠时产生歧义。公式省略完整异常、副作用与浮点特殊值细节，具体行为仍以来源为准。

`requires`、位段映射和摘要是声明式数据，不能作为脚本执行。Python 数据审核工具已实现部分上下文检查，后续应用解码器仍需接入这些规则，并实现剩余运行状态检查。

## 提取与复现

使用 Python 3.10+ 标准库：

```sh
git submodule update --init upstream/riscv-isa-manual
python tools/import_manual_instructions.py
python tools/review_manual_instructions.py
python tools/instruction_context.py
python -m unittest discover -s tools -p 'test_manual_instructions.py'
```

导入前检查手册提交及未修改状态。总表按打印的 bit 位置解析，压缩指令按实际 16 位列解析；特权 Bytefield 表按其显式 bit 标头处理，不能直接把加宽的绘图比例当成编码位宽。向量指令由分配表、格式图和正文规则展开。只有手册明确给出关系时，才从基础编码派生 Zfa、Zabha、Zfinx 或别名变体。

工具只重写自身命名空间中的 `manual-*.json`，不删除其他来源文件。后续若允许多来源包，需另外定义合并与冲突规则。

## 本轮全量复核

全部条目检查身份唯一性、文件索引、双语摘要、来源与许可、位宽、扩展名、位段边界、固定值、掩码/匹配值、立即数位序、寄存器映射、枚举、约束及来源行范围/片段指纹。另用固定机器码验证基础、浮点、压缩、向量、CFI 等代表性编码，检查保留编码拒绝，并比较重新提取结果与每一份已存 JSON 是否一致。

已审阅 **68 组不同指令名之间的编码重叠**，分别记录为别名、提示特化、MOP 重定义、操作数条件分区，或互斥扩展的空间复用；未知重叠使审核失败，不任意按文件顺序消歧。完整列表见本地 `instruction-review.json`。

审核中修正的边界包括：

- RV64 总表标题中提到 RV32 的继承关系，不意味着该行也能在 RV32 执行。
- RV32 Zilsd 的 `LD/SD` 与 RV64 同名指令编码相同，但使用不同语义和寄存器对约束。
- `FENCE` 表的绘图跨度和 `FLQ` 的跨空白单元格，结合独立格式图确认实际位宽。
- VAESDF.VS 图中 `101001` 后多出的反引号，结合本章独立分配表确认，不能当成变量字段。
- `C.ADDI16SP` 图中的十进制寄存器常量 2、压缩寄存器 prime 的不同字符，以及 Zcmp 的 s0–s7 非连续整数寄存器映射。
- `CM.JT/JALT` 的索引分区、`VID.V` 的 `vs2=0`、RV32 压缩移位高位，以及 AES64KS1I 的轮编号限制。
- 不把 `Zero/Zeros` 等下一条指令的锚点标题误当成扩展名称。

这里的审核覆盖已生成数据及其提取规则，不等同于运行每条指令或完成硬件模型一致性认证。向量运行上下文、CSR 读写抑制、访存异常及权限等完整执行语义仍须遵循规范。

## 上下文全量扫描

对全部 **1,323 个编码变体**进一步构造 **2,497 个 XLEN 有效编码样本**，扫描 **191,427 次寄存器编号赋值**及 **1,349 个应被拒绝的保留位赋值**。每个变体均记录上下文扫描结果；数据工具测试共 **30 项通过**。统计可通过上述命令重新生成。

本轮补充或修正：

- E 基础架构的寄存器编号限制同时覆盖 M、CSR、整数/浮点转换、向量标量操作等扩展；f/v 寄存器不因编号大于 15 而被拒绝。
- 浮点 `rm=5/6` 的保留编码；动态舍入 `rm=7` 在缺少 `frm` 时保持待检查，`frm=5/6/7` 不作为有效模式。
- RV32 Zilsd、RV32 Zdinx 及宽 CAS 的偶数寄存器对，按实际操作数宽度及 XLEN 生效，不误限单精度目的寄存器或 RV64 的单寄存器双字操作。
- `CM.MVSA01` 的不同目的寄存器要求、E 模式的保存寄存器列表范围，以及整组向量寄存器传送的编号对齐。
- 压缩影子栈指令的 `Zcmop` 条件，以及 BF16 共用的半精度传送指令所属关系。
- `vset*` 与整寄存器访存不要求旧 `vtype.vill=0`；依赖 `vtype` 的普通指令仍检查 `vill`。
- 归约和特定掩码操作的 `vstart=0` 条件；密码元素组的 SEW、EGS、容量与长度倍数，以及向量无进位乘法/BF16 的元素宽度条件。

`tools/instruction_context.py` 的 `check_context` 仅检查已知事实，返回：

| 结果 | 含义 |
| --- | --- |
| `rejected` | 已提供事实违反编码、位宽、扩展或已实现的上下文规则 |
| `needs-context` | 缺少必要状态，或该项运行状态检查尚未完整实现 |
| `checks-passed` | 本工具已实现且适用的检查通过，不是指令必定无异常执行的保证 |

传入的扩展集合必须是调用方已展开依赖的能力集合；工具不自行假设完整 ISA 配置。缺少 `frm`、FS/VS、`vtype`、`vstart`、SEW、VLEN/LMUL 等状态时不会静默当作有效值。CSR 存在性/访问规则、虚拟化控制、页表/PMP/PMA、有效地址，以及尚未实现的完整寄存器组重叠判定，均保留明确的待检查项。

## 来源与许可

数据依据 RISC-V International 及其贡献者的 ISA Manual，进行了格式转换、名称规范化、中英文摘要、公式化说明及编码约束整理。沿用 `CC-BY-4.0` 署名，许可证见 `app/src/main/assets/licenses/CC-BY-4.0.txt`，第三方声明见 `app/src/main/assets/THIRD_PARTY_NOTICES.txt`。

## 应用查询入口

首页搜索框下方提供 CSR / INST 分页，可点击标签或左右滑动切换；两页共用搜索词、RV32/RV64、执行权限、扩展和来源筛选，并分别保留列表位置。扩展多选匹配任一关联项，保留自动关联前置扩展的规则，不将筛选选项视为完整的执行环境。

INST 支持名称与中英文简短描述搜索，以及 `0x` 十六进制、`0b` 二进制编码反查；无前缀时支持 4 / 8 位十六进制和 16 / 32 位二进制，允许空格和下划线分组。名称匹配排在描述匹配之前，英文描述按完整单词匹配；各类内部按 M、S、H（含 HS）、VS、U、D 权限顺序排列，再优先名称精确匹配；编码反查保留别名、HINT 和扩展重叠候选，并检查当前 XLEN 的静态编码限制。

指令详情展示编码变体、16 / 32 位布局、重组后的寄存器和立即数操作数、执行条件、枚举值与规范来源。执行条件说明默认收起；编码匹配不代表已确认当前机器状态可执行。详情的 RV32/RV64 切换沿用全局筛选。
